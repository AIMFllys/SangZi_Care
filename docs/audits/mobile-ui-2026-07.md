# 移动端 UI 全路由审计（2026-07）

> 审计日期：2026-07-13
> 浏览器：Microsoft Edge（Chromium）
> 范围：16 个路由 × Elder / Family 两种角色 × 7 个视口，共 224 个确定性页面状态

## 目标

本轮审计验证以下移动端约束：

1. 底部导航固定、五项等分、图标与文字处于同一水平基线，中间项不再上凸。
2. 页面根节点不承担滚动；需要滚动的页面只保留一个明确内容滚动区。
3. 320px 窄屏到 480px 手机宽度不出现横向溢出、按钮炸裂或被底栏真实遮挡。
4. 核心内容在可容纳时优先一屏展示；长表单、健康卡片、详情和横屏矮视口允许局部纵向滚动。
5. 可见交互目标不小于 44px；适老化高频操作优先采用 48–64px。

## 改造前问题证据

| 问题 | 改造前证据 | 根因 |
|---|---:|---|
| 隐藏底栏页面仍多出底部空间 | 页面高度额外增加 88px | 全局内容区无条件预留底栏高度 |
| 首页 SOS 与底栏相交 | 26px | 页面和固定导航分别持有视口高度，滚动/安全区所有权重复 |
| 用药主操作与底栏相交 | 48px | 提醒页固定动作区未纳入壳层高度模型 |
| 中间导航项上凸 | 五项 top/bottom 不一致 | 中间项采用独立浮动几何，而非统一网格 |
| 设置页底部留白及内容挤压 | 重复 `.device-wrapper` / `.page-content` | 页面内部重复全局壳层 |
| 家庭详情大面积无样式 | JSX 类名与 CSS Module 不一致 | 组件重构后样式文件仍是旧结构 |

## 本轮实现

- `ClientShell` 按路由划分 `tabbed`、`detail`、`immersive`，统一持有视口高度和安全区。
- `TabBar` 使用 5 列等分的 64px 网格；中间项与其他四项共享相同 top、bottom 和高度。
- 登录、引导、聊天详情、家庭详情、语音等沉浸/详情页不显示全局底栏。
- 首页、健康、用药、消息、设置等页面只让指定内容区滚动。
- 聊天页以消息列表为唯一滚动区，输入栏适配 `visualViewport` 键盘高度。
- 320px 健康页主按钮修正为网格可用宽度，不再出现 `100% + margin` 的 16px 几何溢出。
- 绑定关系标签提升到 48px 高度。
- 横屏用药页改为底栏上方的内部滚动，两个主操作均可完整滚入视区。
- 家庭详情在直接访问时主动加载绑定关系，不再错误显示“未找到该用户信息”。

### 改造后仍实际滚动的页面

“主动滚动”定义为 `overflow-y: auto/scroll` 且 `scrollHeight > clientHeight + 1`。下表只列实际发生滚动的状态；所有状态同时激活的纵向滚动区均不超过 1 个。

| 路由 | 发生滚动的状态数 | 视口 |
|---|---:|---|
| `/` | 1 | Family `844 × 390` |
| `/family/[id]` | 8 | 数据较长的 Family 状态覆盖全部视口；Elder 在短屏/横屏发生滚动 |
| `/login` | 2 | Elder / Family `844 × 390` |
| `/onboarding` | 6 | Elder / Family `320 × 568`、`375 × 667`、`844 × 390` |

| `/health/input` | 4 | Elder / Family `320 × 568`、`844 × 390` |
| `/medicine/history` | 2 | Elder / Family `844 × 390` |
| `/messages/[id]` | 2 | Elder / Family `844 × 390` |
| `/radio` | 2 | Elder / Family `844 × 390` |
| `/settings` | 8 | Elder / Family `320 × 568`、`360 × 640`、`375 × 667`、`844 × 390` |

`/messages` 与 `/voice` 在本次确定性数据下没有实际纵向滚动。部分页面声明了滚动容器但内容未超过容器高度，计为非激活，不会形成双滚动。

审计仍会记录被父级滚动容器裁切的离屏目标；这些目标不属于当前可操作区域。最终判定使用裁切后的可见矩形，因此不会把“可滚入视区”误报为“与固定底栏重叠”。

## 验证边界

- 浏览器矩阵使用确定性 API 拦截，目的是隔离布局和交互几何；真实 API 行为由 Vitest、生产构建和后续生产 smoke 分别验证。
- Android WebView 的系统字体缩放、软键盘、麦克风权限和系统返回键在 Android APK 阶段单独验收。
- 截图不替代人工审美复核；本轮同时逐页检查了信息层级、按钮完整性、留白、滚动位置和底栏一致性。
