## 二、认证与角色

**成熟度: 已实现**

### 用户故事
新用户用邮箱完成验证码登录；首次进入选择 Elder / Family 角色；之后按角色切换主题与 TabBar。

### 流程

```
访问受保护路由
  → useAuth → userStore.initialize()
  → 无 token → /login
  → 有 token、无 role → /onboarding
  → 正常 → 目标页
```

登录页：数学图形验证码 → 发邮箱 OTP → 校验 → 写入 `token` / `refresh_token` → 跳转。

启动校验只在最终收到 401 时销毁本地会话；当 `/users/me` 校验本身被页面跳转取消，或直接因临时断网、5xx 等非 401 原因失败时，会保留可续期凭证，并在已有缓存用户时继续当前会话，避免把短暂网络故障误判为退出登录。

### 代码落点

| 层 | 路径 |
|----|------|
| UI | `app/login/page.tsx` · `app/onboarding/page.tsx` |
| Hook | `hooks/useAuth.ts` |
| Store | `stores/userStore.ts` |
| API | `GET /api/v1/auth/captcha` · `POST /api/v1/auth/send-code` · `POST /api/v1/auth/verify` · `POST /api/v1/auth/refresh` |
| 用户 | `GET/PATCH /api/v1/users/me` · `PATCH /api/v1/users/me/role` |
| 表 | `oc_users` · `oc_auth_challenges` |

### 认证挑战安全与并发

- CAPTCHA 答案、邮箱和 OTP 不以明文写库；邮箱隐私索引与答案/OTP 摘要使用由 `JWT_SECRET` 域分离派生的 HMAC pepper。
- CAPTCHA/OTP 均由 `oc_auth_challenge_*` SECURITY DEFINER RPC 原子写入、消费；挑战表强制 RLS，客户端角色与 `service_role` 均不能直接访问表。
- 发码采用「预留 → SMTP 发信 → 按预留版本激活」；发信或激活失败只使相同版本失效并保留 60 秒冷却，较早的慢请求不能覆盖或删除新验证码。
- 邮箱 60 秒限流、OTP 一次消费和最多 5 次猜测均在数据库事务锁内执行，适用于 EdgeOne 多实例。

### 上线前置
- 目标 Supabase 必须先应用 `supabase/migrations/20260713230000_auth_challenges.sql`；仓库内生成 migration 不等于远端已执行。
- CAPTCHA、发码与 OTP 校验没有进程内存降级路径；RPC 缺失或不可调用时会安全返回 503，不能带病上线。
- EdgeOne Production 必须配置 `JWT_SECRET`、`SMTP_*` 以及 Supabase 服务端变量，且不得把这些密钥改成 `NEXT_PUBLIC_*`。

## 三、双端首页

**成熟度: 已实现**

### Elder（`components/home/ElderHomeView.tsx`）
- 问候、时间卡、天气文案（当前为硬编码占位）
- 大语音球 → `/voice`
- SOS 按钮 → `POST /api/v1/emergency/trigger`，页面内显示发送结果；外部电话/推送通道尚未接入

### Family（`components/home/FamilyHomeView.tsx`）
- 只展示当前账号 `active` 绑定中的长辈，可跨看板、健康、用药复用选择
- 今日用药、七日依从率、心率趋势、血压与异常次数均来自一次聚合 API
- 健康与用药按绑定权限分域展示；未授权区明确显示锁定说明，不伪装成零数据
- 页面不再展示「在家休息」等无数据来源的硬编码状态

### 分流
`app/page.tsx`：`user.role === 'family'` → `FamilyHomeView`，否则 → `ElderHomeView`。

主题由 `ClientShell` 根据 `localStorage.user_role` 设置 `data-theme`。

## 四、健康记录

**成熟度: 已实现**

### 看板 `/health`
展示心率、血压、体温等最新值。长辈端固定查询本人；家属端只能查询当前账号已绑定且获授权的长辈，不展示家属本人健康。

### 录入 `/health/input`
- 手动录入多种体征
- 语音录入走 `useVoiceRecognition`（MiMo ASR 优先，服务异常时可在下一次录音降级 Web Speech）
- 中文数字解析写入记录
- 家属切换照护对象时会取消语音任务并清空旧表单，避免把甲长辈的数据保存到乙长辈
- 未获 `can_edit_health` 授权时，数值、录音和保存控件整体锁定

### 代码落点

| 层 | 路径 |
|----|------|
| UI | `app/health/page.tsx` · `app/health/input/page.tsx` |
| 组件 | `HealthCard`（有测试，页面未引用） |
| Store | `stores/healthStore.ts` · `types/health.ts` |
| API | `POST/GET /api/v1/health/records` · `/latest` · `/trend` |
| 表 | `oc_health_records` |

### 权限与一致性
- 所有跨用户读取要求 `active` 绑定及 `can_view_health` / `can_edit_health`；代录要求 `can_edit_health`
- Store 以账号、目标长辈和请求代次隔离缓存及迟到响应；切换目标的首帧也不会渲染旧数据
- 家属首页通过 `/api/v1/family/dashboard` 使用与健康页相同的数据边界

## 六、捂话（家庭消息）

**成熟度: 已实现**

### 能力
- `/messages`：联系人列表（来自家庭绑定 + 最近消息）
- `/messages/[id]`：文字发送；语音发送保留 16kHz 单声道 WAV、PCM 推导的真实时长与转写
- 语音文件由服务端校验为规范 RIFF/WAVE PCM16LE 后写入私有 Supabase Storage，消息表只保存稳定对象路径
- 会话响应只暴露同源鉴权播放地址；播放路由校验 sender/receiver 后生成 10 分钟签名 URL
- 录音、转写和上传阶段均可取消；客户端下载真实音频后播放，切换/结束/卸载会中止请求并清理 Blob URL
- 未读计数、已读标记

### 代码落点
- UI：`app/messages/*` · `MessageList` · `VoiceRecorder` · `ChatBubble`
- Store：`messageStore` · `lib/messageUtils.tsx`
- API：`/api/v1/messages/*`（含 multipart `send-voice`）· `/api/v1/voice/audio`
- 表：`oc_elder_care_messages`；Storage bucket：`SUPABASE_VOICE_BUCKET`（private）

### 运行约束
- Supabase 控制台必须预建 private bucket 并在本地/EdgeOne 配置 `SUPABASE_VOICE_BUCKET`；上传和签名前都会确认 bucket 存在且 `public === false`
- 上传上限 5 MiB、PCM 录音上限 60 秒，客户端时长声明与 PCM 允许 1 秒缓冲偏差；Storage 或入库失败不会追加消息，入库失败会补偿删除对象

## 九、AI 语音助手

**成熟度: 已实现（MiMo 陪伴 + 真实工具调用）**

### 已通
- `/voice` 在 MiMo ASR 后把文本送入 `POST /api/v1/ai/chat`，固定调用 `mimo-v2.5-pro`；回复同时显示文字并通过 MiMo TTS 朗读
- 服务端陪伴提示词要求简短、尊重、不诊断；完整健康数值可调用 `record_health_metric` 写入 `oc_health_records`，来源标记为 `voice_ai`
- 有留存价值的日常内容可调用 `save_murmur` 私密写入 `oc_ai_murmurs`；只有当前对话存在可验证的明确同意时，才通过原子 RPC `oc_share_ai_murmur` 发给全部 active 家属
- 分享后的家庭消息分类为 `murmur`，联系人预览与对话气泡展示“碎碎念”标签；普通文字与语音消息固定为 `chat`
- 会话打开后通过 `/api/v1/messages/read-all` 一次标记全部未读，联系人加载也由每人两次请求收敛为一次
- 意图识别 API：`POST /api/v1/ai/intent`
- 会话摘要 API：`GET /api/v1/ai/summary/{user_id}`（`summaryStore` 存在但 UI 未用）
- `/voice` 已接真实 16kHz 单声道 PCM WAV 录音、MiMo ASR 和 MiMo MP3 TTS；录音、转写、播放均可取消并隔离迟到结果
- 服务端实现位于 `lib/server/mimo.ts`、`lib/server/companion-tools.ts` 与 `app/api/v1/voice/*`；密钥只读 `MIMO_API_KEY`，所有重试共享 45 秒总截止时间
- 用药提醒、健康语音录入和家庭消息均复用同一套真实语音能力；聊天语音原文件另存私有 Storage

### 未通 / 弱
| 项 | 现状 |
|----|------|
| `intentHandlers.ts` | 旧意图分发器仍仅供测试；语音页现已改走 MiMo 原生工具调用，不依赖该分发器 |
| `VoiceBall` / `VoicePanel` | 组件存在；Elder 首页内联语音球，未复用组件 |

### 入口差异
- Elder：首页语音球 → `/voice`（TabBar 在 `/voice` 隐藏）
- Family：Tab 中心为 `/voice`
