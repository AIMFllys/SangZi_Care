# 智护银龄 APP 正式项目汇报 Word 文档设计

## 一、目标

制作一份可直接用于项目宣讲、阶段汇报和评审展示的正式 Word 文档。文档以“智护银龄 APP 做什么、为什么值得做、怎样服务长辈和家属、当前做到什么程度”为主线，配合真实应用截图和少量实践材料，帮助非技术听众准确理解项目价值。

## 二、表达边界

1. 全文使用通俗、严谨的中文，不使用工程术语，不介绍程序结构、开发框架、接口或数据库。
2. 不使用宣传册、画册、海报式表达，不堆砌口号，不夸大社会成效。
3. 调研依据表述为“现有 7 份实地采访记录”，不把记录份数写成受访人数，不虚构问卷样本、满意度、覆盖人数或医疗效果。
4. 应用截图中的姓名和数值均标明为演示数据，不作为真实服务效果证据。
5. 对尚需完善的能力如实说明：紧急求助目前可以在应用内发起和留存，但电话、短信或推送等外部通知渠道仍需继续接入和验证。
6. 明确本应用用于健康记录、用药提醒、家庭沟通和日常陪伴，不代替医生诊断，也不代替急救电话。

## 三、内容结构

1. 封面：项目名称、实践项目归属、文档性质、日期。
2. 项目概况：一句话定位、主要使用者、希望解决的问题、当前版本。
3. 为什么要做：从调研记录归纳长辈、家属和照护场景中的实际困难。
4. 项目总体思路：长辈端强调简单、清楚、语音优先；家属端强调看得见、能协助、有边界。
5. 核心功能：智能语音助手、健康记录、用药管理、家属照护看板、家庭消息与日常分享、家庭绑定和权限、无障碍设置、紧急求助。
6. 典型使用场景：长辈日常自用、家属远程协助、共同完成健康与用药管理。
7. 项目价值：分别说明对长辈、家属、实践教学和智慧医养探索的价值。
8. 当前进展与边界：区分“已经可以使用”“仍需继续完善”。
9. 下一步工作：真实老人试用、提醒到达能力、外部紧急通知、隐私和使用指导。
10. 资料说明：项目资料、调研资料与国家标准来源。

## 四、版式设计

### 1. 总体风格

采用正式、克制、专业的项目汇报版式。正文以黑色为主，仅在封面细线、章节编号和表头中使用深绛红色；辅助色为深灰和浅暖灰。不使用渐变、阴影卡片、装饰性图形和大面积彩色背景。

### 2. 国标参照

- 纸张采用 A4，依据 GB/T 148—1997。
- 版心与页边距参照 GB/T 9704—2012：上 37 毫米、左 28 毫米，并结合图文汇报阅读需要设置下 30 毫米、右 26 毫米。
- 标题、正文、层级序号参照正式汇报材料常用体例：主标题 2 号宋体加粗，一级标题 3 号黑体，二级标题 3 号楷体，正文 3 号仿宋。
- 标点符号遵循 GB/T 15834—2011；数字、日期和计量单位遵循 GB/T 15835—2011。
- 本文是项目汇报材料，不设置党政机关公文的发文字号、版记、印章等要素，也不声称属于法定公文。

### 3. 图片规则

- 每张图片均设置图号、图名和简短说明。
- 应用截图统一放入简洁的细灰边框，不使用手机模型或炫彩底图。
- 同一页最多放置 2 至 3 张手机截图，保证界面文字仍然可辨。
- 调研现场图片不展示可识别的老人正面特写；采用环境或场所照片说明调研背景。

## 五、验收标准

1. 输出可编辑的 `.docx` 文件。
2. 全文无工程术语、无乱码、无占位符、无虚构数据。
3. 关键功能均有准确文字说明，至少包含 6 张真实应用截图。
4. 所有图片有图注，演示画面有演示数据提示。
5. 目录、标题层级、页码、图号和资料来源完整。
6. 使用 Word 渲染为逐页图片并检查全部页面；不存在文字裁切、图片重叠、表格越界、孤行标题或空白页。
7. 文档生成后执行项目原有的 lint、类型检查和构建，不修改应用功能。
